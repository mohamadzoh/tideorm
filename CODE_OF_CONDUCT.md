# Code of Conduct

## Purpose

TideORM is an open source project built through collaboration. This code of conduct exists to keep the project respectful, productive, and welcoming for contributors, maintainers, and users.

By participating in this repository, you agree to follow these standards in issues, pull requests, review discussions, documentation, and other project spaces.

## Expected Behavior

- Be respectful in tone and language.
- Focus feedback on code, design, behavior, and facts rather than on people.
- Assume good intent, especially when discussing bugs, regressions, and review feedback.
- Be open to technical disagreement without becoming hostile or dismissive.
- Help keep discussions clear, relevant, and useful to the project.
- Show patience with contributors of different experience levels.

## Unacceptable Behavior

The following behavior is not acceptable in this project:

- Harassment, intimidation, threats, or personal attacks.
- Discriminatory, hateful, or degrading language.
- Sexualized language, sexual attention, or unwanted advances.
- Trolling, baiting, dogpiling, or intentionally disruptive behavior.
- Repeatedly derailing technical discussions after moderation requests.
- Publishing or threatening to publish private information without permission.
- Any conduct that would make participation feel unsafe or hostile.

## Scope

This code of conduct applies to:

- Repository discussions, issues, and pull requests.
- Review comments and maintainer interactions.
- Documentation feedback and other project communication channels tied to TideORM.

## Reporting

If you experience or witness behavior that violates this code of conduct, report it privately to the project maintainer at `alzoubi528@gmail.com`.

When possible, include:

- A short description of what happened.
- Links, screenshots, or other relevant context.
- Whether there is any immediate safety or moderation concern.

Reports will be handled as discreetly as possible.

## Enforcement

Project maintainers may take any action they believe is necessary to protect the project and its participants, including:

- Requesting a change in behavior.
- Editing, hiding, or removing content.
- Temporarily limiting participation.
- Permanently removing a participant from project spaces.

Enforcement decisions will be based on the severity and pattern of the behavior, with the goal of protecting the health of the project.

## Final Note

Technical rigor and direct feedback are welcome here. Respect is not optional.
